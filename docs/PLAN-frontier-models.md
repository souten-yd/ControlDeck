# 計画: フロンティアモデル（Codex・Claude・OpenRouter ほか）と開発の役割

状態: 計画確定（2026-11-15、利用者の依頼による）。進捗はこの文書の「進捗」と `docs/implementation-status.md`。
区分: 外部への送信と秘密値を扱うので、この計画の PR はすべて **L2**（`docs/POLICY-autonomous-development.md`）。利用者はホームの「承認」から承認する。

## 目的

いまは完全ローカル。これからは ControlDeck から外部のフロンティアモデルにも届くようにし、開発・外部への中継・監査に使う。
複数のプロバイダを自由に使い分け、OpenCode・AI アシスタントなどから同じ入口で使えるようにし、開発の役割（監督・指示者・開発担当・監査）に好きなモデルを割り当てられるようにする。

## 方針（調査と判断）

### 接続の 2 種類

| 種類 | 例 | 認証 | 使い方 |
|---|---|---|---|
| **API プロバイダ** | OpenRouter、OpenAI、Anthropic、Google Gemini、OpenAI 互換の任意の先 | API キー（ControlDeck の秘密鍵で暗号化して保存）。OpenRouter はブラウザでのログイン（OAuth PKCE）でキーを受け取る方式も用意 | ControlDeck の LLM ゲートウェイ経由。モデル名 `cloud:<プロバイダ>/<モデル>` として、ローカルのモデルと同じ一覧に並ぶ |
| **エージェント CLI** | Codex CLI（ChatGPT のプラン）、Claude Code（Claude のプラン） | それぞれの公式 CLI の機器認証（デバイスコード）でログイン。ControlDeck のターミナルで行う | 開発担当・監査などの役割として、サンドボックス／プロジェクトの箱の中で CLI を動かす |

- いずれも OpenAI 互換の API（OpenAI・OpenRouter・Anthropic の互換 API・Gemini の互換 API）に揃え、ゲートウェイの実装を 1 つにする。
- **プランの認証情報（ChatGPT・Claude のログイン）は公式 CLI の中だけで使う。** トークンを取り出して他のアプリや API 呼び出しに流用しない（各社の利用規約上、公式 CLI 以外での利用は認められていない）。だから「エージェント CLI」は別の種類として扱う。
- このPCには Codex CLI 0.169.0（ログイン済み）と Claude Code 2.1.325 が既に入っている。

### 外部への送信の制御（最重要）

- **既定はどこからも送らない。** 呼び出し元ごと（AI アシスタント・OpenCode・Workflow・Add-on）に、外部モデルを使ってよいかを設定で選ぶ。
- **Add-on の local_only（PatentBuddy など）は外部モデルに決して流れない。** 既存の local-only の境界を変えない。
- OpenCode はプロジェクトごとに「外部モデルを使わない（機密）」を付けられる。
- 外部への呼び出しはすべて記録する（日時・呼び出し元・プロバイダ・モデル・トークン数・概算費用。本文は記録しない）。プロバイダごとに月の上限額を設け、超えたら止める。
- 画面では外部モデルに「外部」の印を付け、選んだときに送信先が分かるようにする。

### 役割

| 役割 | すること | 既定の割り当て |
|---|---|---|
| 監督 | 計画、関門の判定、L2 の承認依頼の作成 | ローカル（利用者が外部へ変更可） |
| 指示者 | 作業を分け、開発担当への指示書を書く | ローカル |
| 開発担当 | 実装・テスト作成 | ローカル（OpenCode の build） |
| 監査 | 独立したレビュー（実装と別のモデル） | ローカル（reviewer 子エージェント） |
| 中継 | 外部の情報・モデルへの問い合わせを代行（送ってよいものだけ） | なし（外部を有効にしたときだけ） |

役割ごとに「ローカルのモデル」「外部の API モデル」「エージェント CLI」のどれかを選ぶ。OpenCode の build・reviewer・advisor と、今後の開発チーム（監督→指示者→開発担当→監査の繰り返し）がこの割り当てを使う。

## 段階と PR

1. **F1 backend**: API プロバイダの登録（暗号化したキー）、ゲートウェイの振り分け（`cloud:` のモデル）、外部送信の制御（呼び出し元ごとの許可・local_only の遮断）、記録と月の上限。外部へは実際に送らないテスト（モック）。
2. **F2 画面（Fable）**: Models タブに「フロンティアモデル」。プロバイダの接続（キーの入力・OpenRouter のログイン）、使うモデルの選択、外部送信の許可、上限と使用量。
3. **F3 エージェント CLI**: Codex・Claude Code のログイン状態の確認と、機器認証のログインを ControlDeck のターミナルで行う導線。箱の中での実行。
4. **F4 役割**: 役割の割り当て画面（Fable）と、OpenCode・AI アシスタントへの接続。
5. **F5 開発チーム**: 監督→指示者→開発担当→監査の繰り返しを ControlDeck の中で動かす（いま統括が手で行っている流れを機械化）。

## 確かめられないこと

- 実際の外部 API への送信は、利用者が API キーを設定するか、CLI でログインしてから確かめる（OpenRouter には無料のモデルがある）。
