# 方針: 自律的な開発と、誰が判断するか

決定: 2026-11-15（利用者の承認済み）。この文書と `config/change-policy/*.json` が正。
利用者の操作と判断を最小にするため、変更ごとの判断者を危険度で機械的に決める。

## 役割

| 役割 | 担当 | すること |
|---|---|---|
| 利用者 | 人 | 目標・優先順位を決める。L2 の承認・却下（ワンタップ）。方針そのものの変更 |
| 統括 | Claude（このリポジトリの開発エージェント） | 計画、ローカル LLM への指示、独立した監査、関門の判定、マージ、Release |
| 実装 | ローカル LLM（OpenCode、サンドボックスまたはプロジェクトの箱の中） | 実装・テスト作成。機密を外に出さずに量をこなす |
| 機械 | ControlDeck | 区分の判定、隔離、検証用インスタンス・ミラー、自動適用と自動の巻き戻し、通知 |

## 区分（`./deck.sh change-class --repo <リポジトリ> --base <基点> --policy <規則>`）

| 区分 | 対象（例） | 進め方 | 利用者 |
|---|---|---|---|
| **L0 自動** | 文書・テストだけ、CodeDEV のアプリ・ゲーム | 関門を通ればマージまで自動 | 何もしない |
| **L1 自動＋事後報告** | ControlDeck・拡張機能の通常の改修（画面、ゲートウェイ、OpenCode 連携、拡張機能の機能追加） | 関門を通ればマージ → 正式 Release → 本番は使われていない時間に自動適用 → 異常なら自動で前の版へ戻す | 通知を見るだけ |
| **L2 要承認** | 認証・権限・秘密値、AI の権限や外部への送信・隔離の規則、利用者データの移行・削除、更新や隔離の仕組みそのもの、費用や外部公開を伴うもの（QNAP への配備など） | 関門を通した上で、平易な要約と危険度を通知し、承認されたら進める | 承認／却下を押す |

- 1 つの変更の区分は、含まれるファイルの区分の最大。迷うものは上に寄せる。
- 区分は `config/change-policy/` の規則（場所と変更内容）で決める。内容の規則は、境界を実際に強制するコード（ControlDeck なら `backend/app`）だけに当てる。
- 規則・この文書・AGENTS.md・更新と隔離の仕組みを変える変更は、それ自体が L2。

## 関門（L1・L2 共通。L0 は該当する分だけ）

1. 全テスト（ControlDeck: `./deck.sh test`、frontend build。PatentBuddy: `bash scripts/verify.sh`）。
2. 画面の変更があれば `./deck.sh e2e`（検証用インスタンス、アクセシビリティ）と UI 検証。
3. ControlDeck 本体の変更は、サンドボックスのミラーで起動と主な流れを確かめる。
4. 独立したレビュー: 実装した LLM とは別の目（reviewer 子エージェントと統括の監査）。重大・要修正の指摘が 0 件。
5. 実装した LLM の「合格」報告をそのまま使わず、統括が自分で関門を再実行する。

## 本番への適用（L1 の自動適用）

- 正式 Release だけを取り込む（プレリリース・下書きは取り込まない）。
- 本番の ControlDeck が使われていない時間（LLM の推論・OpenCode のセッション・拡張機能のジョブが無い）に適用する。
- 適用前にバックアップ、適用後に深い確認（health・画面・ゲートウェイ・拡張機能の health）を行い、異常なら自動で前の版へ戻して通知する。
- 自動適用は設定で止められる。止めているときは「更新あり」を通知するだけにする。

## L2 の承認の流れ（統括の手順）

1. 関門を通し、PR を作る（Draft にしない）。
2. `./deck.sh approval request --repo <owner/name> --pr <番号> --title "<平易な題名>" --summary "<何が変わり、利用者に何が起きるか>" --risk "<なぜ承認が要るか>"`（区分の理由は `./deck.sh change-class` の guarded をそのまま使う）。
3. 利用者が承認すると ControlDeck がその時点のコミットだけをマージする。PR が変わっていたらマージしない（依頼し直す）。
4. 承認されると ControlDeck が次の版の正式 Release を出し（ControlDeck 本体だけ）、本番は使われていなければ 10 分の待ちを飛ばしてすぐ適用する。
