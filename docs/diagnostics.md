# 診断の一覧

異常を見つけたら、同じものを次に見つけられるようにここへ足す（決まりは `AGENTS.md` の
「不具合・診断・テストの決まり」）。仕組みは `backend/app/diagnostics/`、画面は「診断」、
AI へは MCP の道具 `control_deck.diagnostics` と「AI 用レポートをコピー」。

## 常駐の記録（`recorder.py`、軽いものだけ）

| 何を見つけるか | どう見るか | きっかけ（根拠） |
|---|---|---|
| 警告・エラー | WARNING 以上のログを traceback つきで記録（同じ内容は 1 分 20 件まで） | 落ちた後に手掛かりが journal に埋もれる |
| 応答の詰まり（画面が遅い） | event loop が 1 秒以上返らないとき、loop の外の thread から塞いでいた関数の stack を撮る | 2026-11-17 会話履歴の読み込みが遅い。複数の API が同時に返る＝loop が塞がれていた |
| 遅い API | 要求ごとの所要時間、2 秒以上を記録、API ごとの p50/p95 | 同上 |
| 画面側の時間（携帯で遅い） | AI アシスタントを開いてから一覧・会話の取得・描画までの時間と、その間の API の時間（往復・待ち・大きさ）を画面から送る（`lib/clientTiming.ts`、`POST /diagnostics/client`）。レポートの「画面側の時間」に p50/p95 | 2026-11-17 会話の読み込みが遅い。サーバー側は 2 秒未満・詰まり 0 で、通信か描画かを分けられなかった |
| 画面の寸法（iPhone で上下が切れる） | 開いたとき・寸法が変わったときに、報告される高さ（innerHeight・visualViewport）、画面の実寸、Safe Area、殻と入力欄の位置を送る。レポートの「画面の寸法」に新しい順 | 2026-11-17 ホーム画面アプリで下が切れる。「100vh が縮む」前提の修正（#428）で直らず、実機の値で原因が分かった（WebView 自体が 59 短くなる。screen 932 / inner 873） |
| メモリ不足の前触れ | 30 秒ごとに空き・swap・VRAM・RSS 上位と unit。空きが少ないときの上位を記録 | 2026-11-16 Strata が 65〜67GB で OOM、何が重なったかが残っていなかった |

## journal から抜き出すもの（`journal.py`、開いたときに読む）

| 何を見つけるか | どう見るか | きっかけ |
|---|---|---|
| 本体の再起動と理由 | systemd の記録（watchdog / 終了処理の詰まり / OOM / 異常終了 / 更新 / 手動）。止める指示の後の watchdog は「終了処理の詰まり」 | watchdog に落とされた回数と理由が分からなかった。2026-11-17 の 5 回はすべて終了処理の詰まりだった |
| 常駐の異常終了 | control-deck-* / cdapp-* / cd-* の Failed / OOM / Watchdog | 並べ替えのモデルが 2 日で 51 回落ちていたのに誰も気づかなかった |
| OOM で強制終了されたプロセス | カーネルの OOM killer の記録（プロセス・RSS・unit） | 2026-11-16 Strata の OOM |

## 自己診断（`selftest.py`、押したときだけ）

DB の quick_check、ディスク、メモリ、詰まり、失敗した unit、ローカル LLM、画面の build、必要なコマンド、
メトリクス収集。backend のテストもここから流せる（本番のデータと機械全体の常駐に触らない設定）。

| 何を見つけるか | どう見るか | きっかけ |
|---|---|---|
| 音声入力が選んだエンジンで動いていない・フィルターが働いていない | 選んだ ASR（Models の TTS / ASR）が未導入で別のエンジンが使われている（英語は日本語のエンジンへ回さない）、失敗して控えへ回った、入力フィルター（声の判定）が未導入。捨てた区切りの数も出す | 2026-11-19 ASR のエンジンを選べるようにした。選んだのに黙って別のものが動くと気づけない |
| 会話の資料の再ランクが遅い | AI アシスタントの回答前の再ランク（会話の資料）が 3 秒の上限で打ち切られた回数と最長の秒数 | 2026-11-20 本番: GPU が埋まり reranker が CPU で動き、挨拶 1 つで思考の開始まで 23 秒（再ランク 22.6 秒）かかった |
| 音声合成の失敗・Supertonic 3 の保管庫の欠け | 直近の合成の失敗と、保管庫（`data/archives/supertonic-3`）のソース・重み・wheel がサイズどおり揃っているか | 2026-11-19 上流が開発終了。保管庫が唯一の入手元になるので、欠けたら気づけるようにする |

## 足すとき

1. 常に見張っても軽いか？ → 軽ければ `recorder.py` に、重ければ `selftest.py` の検査にする。
2. 記録には「何が・いつ・どれだけ・原因の手掛かり（stack・unit・値）」を入れる。秘密は入れない
   （レポートで伏せるが、そもそも記録しない）。
3. `report.py` の Markdown と画面に出す。上の表に 1 行足す。
4. `tests/test_diagnostics.py` に、その異常を作って記録されることを確かめるテストを足す（目録で重複を確認）。
