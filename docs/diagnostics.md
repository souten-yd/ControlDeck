# 診断の一覧

異常を見つけたら、同じものを次に見つけられるようにここへ足す（決まりは `AGENTS.md` の
「不具合・診断・テストの決まり」）。仕組みは `backend/app/diagnostics/`、画面は「診断」、
AI へは MCP の道具 `control_deck.diagnostics` と「AI 用レポートをコピー」。

## 常駐の記録（`recorder.py`、軽いものだけ）

| 何を見つけるか | どう見るか | きっかけ（根拠） |
|---|---|---|
| 警告・エラー | WARNING 以上のログを traceback つきで記録（同じ内容は 1 分 20 件まで） | 落ちた後に手掛かりが journal に埋もれる |
| 応答の詰まり（画面が遅い） | event loop が 1 秒以上返らないとき、loop の外の thread から塞いでいた関数の stack を撮る | 2026-11-17 会話履歴の読み込みが遅い。複数の API が同時に返る＝loop が塞がれていた |
| 遅い API | 要求ごとの所要時間、2 秒以上を記録、API ごとの p50/p95 | 同上 |
| メモリ不足の前触れ | 30 秒ごとに空き・swap・VRAM・RSS 上位と unit。空きが少ないときの上位を記録 | 2026-11-16 Strata が 65〜67GB で OOM、何が重なったかが残っていなかった |

## journal から抜き出すもの（`journal.py`、開いたときに読む）

| 何を見つけるか | どう見るか | きっかけ |
|---|---|---|
| 本体の再起動と理由 | systemd の記録（watchdog / OOM / 異常終了 / 更新 / 手動） | watchdog に落とされた回数と理由が分からなかった |
| 常駐の異常終了 | control-deck-* / cdapp-* / cd-* の Failed / OOM / Watchdog | 並べ替えのモデルが 2 日で 51 回落ちていたのに誰も気づかなかった |
| OOM で強制終了されたプロセス | カーネルの OOM killer の記録（プロセス・RSS・unit） | 2026-11-16 Strata の OOM |

## 自己診断（`selftest.py`、押したときだけ）

DB の quick_check、ディスク、メモリ、詰まり、失敗した unit、ローカル LLM、画面の build、必要なコマンド、
メトリクス収集。backend のテストもここから流せる（本番のデータと機械全体の常駐に触らない設定）。

## 足すとき

1. 常に見張っても軽いか？ → 軽ければ `recorder.py` に、重ければ `selftest.py` の検査にする。
2. 記録には「何が・いつ・どれだけ・原因の手掛かり（stack・unit・値）」を入れる。秘密は入れない
   （レポートで伏せるが、そもそも記録しない）。
3. `report.py` の Markdown と画面に出す。上の表に 1 行足す。
4. `tests/test_diagnostics.py` に、その異常を作って記録されることを確かめるテストを足す（目録で重複を確認）。
